# Mobile privacy and account deletion

`GET /api/v1/mobile/privacy` exposes only the active provider/model, verified disclosure readiness and public legal configuration. It never returns credentials or a custom API URL. The client uses the consent endpoint's versioned recipients, data-use and retention text; changing any disclosure field requires fresh consent. Missing or mismatched disclosure blocks new AI work. Provider account settings and actual routing must be checked independently; the API does not infer account-level prompt logging or promise zero retention.

Public legal configuration uses `PUBLIC_OPERATOR_NAME`, `PUBLIC_OPERATOR_COUNTRY`, `PUBLIC_SUPPORT_EMAIL`, `PUBLIC_APP_RETENTION` and `PUBLIC_LEGAL_APPROVED=true` only after the operator approves the policy and Terms. Missing details remain visibly pending in the app. These values contain no secrets.

Deletion has two steps. An authenticated, confirmed `POST /api/v1/mobile/account/deletion` accepts a client-generated high-entropy `receipt` and permanently fences the account. `POST /api/v1/mobile/account/deletion/complete` uses that receipt in the JSON body to resume cleanup even after Auth has been removed. Only its SHA-256 digest is stored on the server. The receipt does not permit reading CV data or selecting another user. Persist the receipt before starting and clear it only on confirmed completion. The receipt is a capability: never place it in URLs, logs or analytics.

Local SQLite fences serialize with document writers. Supabase triggers serialize account deletion with metadata and Storage object writes, rejecting any insert/update after the fence. Existing authenticated work and the owner's active worker task are cancelled; the worker itself continues serving other accounts. Each new AI dispatch also checks the local fence. A provider request already sent cannot be recalled. Cleanup removes the owner's engine resumes, revisions/receipts, linked jobs, previews, improvements and queue/application data; scans the entire private original-file namespace, including interrupted uploads; removes Supabase registries, progress, consent and profile rows; hard-deletes Auth last; then acknowledges completion. A separate durable deletion worker resumes confirmed server-side requests every ten seconds, including after device loss or server restart. Repeating any step is safe. Content-free account fences and receipt hashes remain to prevent resurrection and acknowledge retries.

Artifact owner columns are additive and backfilled only from proven source-resume links. Unattributed legacy artifacts must never be assigned to or deleted for an arbitrary account. A separate inventory of any pre-existing unlinked artifacts is required before claiming historical data cleanup is exhaustive. Provider retention, backups and exported copies are not erased by live account deletion. A restore procedure must reapply deletion fences before serving restored data; backup expiry and restore tests remain launch checklist items.

The current Railway service is one replica with one Uvicorn worker and a mounted mobile SQLite database. Scaling must keep the durable writer fence shared. Never give client roles access to the deletion table or its private trigger functions.

Runtime facts confirm `openrouter` with `anthropic/claude-sonnet-5.5`. The deployed disclosure restricts new consent-scoped requests to `anthropic` with no fallback. Account-level logging/safety retention remain unverified and the notice says so.
